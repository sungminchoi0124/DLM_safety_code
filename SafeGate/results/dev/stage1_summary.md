## 게이트 발동률 (응답 앞 16자리, short 토큰 집합)

거부·순응 질량(열린 자리 평균, 스텝별)의 분포:

| | m_ref p50 / p90 / 최대 | m_cmp p50 / p90 / 최대 |
|---|---|---|
| 유해 | 0.0005 / 0.0066 / 0.031 | 0.0007 / 0.012 / 0.028 |
| 무해(GSM8K) | 0.0 / 0.0 / 0.0005 | 0.00001 / 0.0002 / 0.0022 |

- 무해 쪽은 두 질량이 사실상 0이라 a, b를 조금만 올려도 GSM8K에서는 발동하지 않음(b = 0이어도 a ≥ 0.005면 0/30).
- 유해 쪽도 두 질량이 동시에 큰 경우는 드묾: a, b가 모두 0보다 큰 가장 낮은 조합(0.005, 0.005)에서 발동 1/30, 순응만 보는 (0, 0.005)에서 4/30.
- 거부만 보는 쪽은 자주 발동: (a, b) = (0.005, 0)에서 23/30, (0.01, 0)에서 12/30.
- 인필(프롬프트 마스크) 창의 거부 질량은 최대 0.002로 거의 0: 인필에는 거부 표현이 나오지 않음(사용자 턴을 채우는 자리라 당연). short 집합으로는 인필 게이트가 성립하지 않음.
- RAEC 집합은 흔한 토큰("to", "how", "help" 등)이 섞여 GSM8K에서도 질량이 큼(m_cmp p90 0.14). 낮은 임계값에서 무해 발동률이 100%.

## 미리 정한 규칙의 적용

- 규칙: 응답 창 + short 집합, 무해 발동률 ≤ 1/30 중 유해 발동률 최대 → **(a, b) = (0.005, 0)**, 유해 23/30(76.7%), 무해 0/30. 중단 기준(30%)은 넘음.
- 단, b = 0이라 이 게이트는 "거부와 순응이 경합할 때"가 아니라 **"거부 질량이 조금이라도 있을 때"** 발동한다. 원래 가설(양쪽 경합)에 해당하는 b > 0 조합은 유해 발동률이 최대 4/30이라 중단 기준에 못 미친다.
- 결론: 경합 가설 자체는 개발셋에서 지지되지 않았다. 규칙이 고른 "거부 신호 게이트"가 실제로 출력을 바꾸는지는 1b단계(개발셋에서 게이트를 켠 실행)로 테스트셋 전에 확인한다.
