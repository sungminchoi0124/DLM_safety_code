# RQ3 다음 계획: 새 Workspace (2026-11-23 수정)

기존 `dija` Workspace는 `/root`가 노드 공용 XFS라서 inode와 용량이 바닥나 쓸 수 없다. 이 문제는 우리 쪽에서 해결할 수 없으므로 새 Workspace로 옮긴다. 아래는 지금까지 나온 결과(`results/e0_5/`, `results/traces_2026-11-22/`)를 반영한 계획이다.

## 0. 지금까지 확정된 것 (다시 돌리지 않음)
- **E0.5:** 84% vs RAEC 8%는 판정 구간 차이다. DIJA는 인필을 보고, RAEC는 assistant 답변을 본다. judge와 스텝·cfg는 원인이 아니다.
- **시드 0, 100문항의 라벨, 연산량, 텍스트 품질은 확정이다.**
  - Fast-dLLM(A)은 연산량을 42%까지 줄여도 해로움과 품질이 R과 같다.
  - Prophet(P)은 인필 기준 해로움을 85에서 43으로 줄인다. 원인은 품질 저하다. 일찍 종료하면서 늦게 채워지는 인필을 한 번에 몰아서 채우기 때문이다.
  - D(DiffuGuard)는 해로움 32다.
- **Prophet 구현:** R trace로 계산한 종료 시점이 실제 종료 시점과 100/100 같다. 이미 커밋된 위치를 복사하는 경향도 확인했다.
- **프로브는 성공 기준 미달이다.** AUROC 0.60~0.68로 기준 0.85에 못 미친다. 그래서 s\*, n_τ, H1이 보류 상태다. 이번 계획의 중심은 이것이다.

## 2. 만든 직후 점검 (Claude가 SSH로, GPU 안 씀). 하나라도 실패하면 실험하지 않는다
1. **SSH 주소 갱신:** VESSL SDK로 새 ID와 SSH 주소를 읽어 `~/.ssh/config`를 고친다. 공개키는 이미 등록되어 있다.
2. **저장소 쓰기 시험**
   - `findmnt /root`, `df -h /root`, `df -i /root`를 확인한다.
   - **실제 쓰기 시험**을 한다. 2 GB 파일 1개와 작은 파일 5만 개를 쓰고 지운다.
   - `df`의 여유 공간만 믿지 않는다. dija는 68 GB가 남았다고 나왔지만 실제로는 0이었다.
3. **자동 종료 준비:** Workspace 안에서 `vessl whoami`가 되는지 확인한다. 이번에는 `/root`에 바로 결과를 쓰므로, Workspace가 스스로 꺼져도 결과가 남는다.

4. **테스트:** `pytest RQ3/tests`가 전부 통과해야 한다(현재 33개).

## 4. 코드 수정 (로컬 CPU, 새 Workspace 준비와 동시에)
- **영역별 은닉 상태**
  - `TraceRecorder`가 은닉 상태를 세 가지로 저장하게 한다.
    - 지금처럼 추적 위치 전체의 평균
    - 인필 위치(프롬프트 마스크)만의 평균(`hidden_infill`)
    - 답변 위치만의 평균(`hidden_tail`)
  - 프로브 미달의 1순위 원인 후보는 풀링 희석이다. 인필 약 90칸과 답변 128칸을 함께 평균 내고 있다.
  - 저장량은 설정당 약 3배가 된다(R 기준 약 1.1 GB).
- **풀링 영역 선택:** `analyze fit/score`에 `--region all|infill|tail`을 추가하고, CPU 테스트를 추가한다.
- **결과 저장 위치:** `run_all_traces.sh`는 `/root` 직접 쓰기로 되돌린다(`WORK_OUT` 없이). 끝나면 Workspace가 스스로 꺼진다. 로컬 감시 작업은 쓰지 않는다. 지난번에 PC 메모리 부족으로 중단됐다.

## 5. 실험 순서 (GPU)

| 순서 | 무엇 | 설정 | 예상 시간 | 왜 |
|---|---|---|---:|---|
| 1 | 시험 | R `LIMIT=5` | 5분 | 새 저장 항목과 재현(RQ1 해시)을 확인한다 |
| 2 | 프로브 데이터 | R 시드 0, 1, 2 | 각 35분 | 안전 사례가 시드당 15개뿐이라 늘린다 |
| 3 | 프로브 데이터 | D 시드 0, 1 | 각 40분 | 안전 사례를 늘리고 H3에 쓴다 |
| 4 | — | **여기서 멈추고 프로브를 다시 학습한다** (로컬 또는 Workspace CPU) | — | region별, R만 / R+D별 AUROC. 기준 0.85 |
| 5a | 프로브가 기준을 넘으면 | P, P_argmax, A0.9/0.7/0.5 (시드 0) 다시 돌리기 | 각 15~35분 | 새 은닉 상태로 s\*와 H1(종료 시점 > s\*), flips를 계산한다 |

- **설정마다 남길 것:** 판정은 두 기준 모두 한다(`run_traces.sh judge`). 생성 텍스트와 eval JSON은 `/root/rq3-outputs`에 남긴다. 지난번처럼 사라지지 않게 하기 위해서다.
- **Llama-Guard:** 계속 쓰지 않는다. 필요해지면 그때 라이선스를 승인받는다.

## 6. 운영 규칙 (이번에 배운 것)
- 긴 실행 전에는 `df -i /root`와 쓰기 시험을 한다.
- **과금**
  - 실행 스크립트 끝에서 Workspace가 스스로 꺼지게 한다.
  - 시작 전에 VPN을 켠다. SSH는 연세 VPN에서만 된다.
  - 재시작할 때마다 SSH 포트를 SDK로 다시 읽는다.
- **보안**
  - 로그와 출력에서는 진행 숫자, 에러 줄, 해시만 본다. 생성 텍스트는 Workspace 밖으로 가져오지 않는다.
  - 로컬로 가져오는 것은 숫자 결과(`results/`)뿐이다.
